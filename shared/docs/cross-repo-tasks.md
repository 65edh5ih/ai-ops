# リポジトリ横断タスク（`.ops-sync/tasks/`）の使い方

「このリポジトリでやったのと同じ作業を別リポジトリでもやってほしい」等、**別リポジトリでの作業が
必要になったとき**の依頼経路。1セッション=1リポジトリの制約下で、依頼を ops-sync 経由で対象リポジトリの
手元（`.ops-sync/tasks/`）まで物理的に届ける。Notion 等の外部ツールへの転記は不要。

経路: 依頼元から `種別: task` を ops-sync へ出す（正本への直接 PR か `.ops-sync/outbox/` 提案。選び方は
[`docs/outbox-proposal.md`](outbox-proposal.md)）→ ops-sync の `tasks/<owner>/<repo>/` → sync で
対象リポジトリの `.ops-sync/tasks/` へ配布 → 対象リポジトリのセッションが実行 → `種別: task-done` で消化。
途中に ops-sync 側の PR と同期 PR（対象）が挟まり、**オーナーが2回マージして初めて届く**＝届いている
タスクは承認済みとみなしてよい。

## 依頼する側（タスクを書くとき）

本文を読むのは**このセッションの文脈を何も持たない**、対象リポジトリのエージェント。次を必ず含める:

1. **目的（なぜ）**: 何を達成したいか。依頼元で何があったか。
2. **作業内容（何を）**: 具体的に。依頼元リポジトリのファイルは参照できないので、必要なコード・設定・
   手順は**本文に貼り込む**（「◯◯リポジトリの △△ を見て」は書かない——見えない）。
3. **完了条件**: 何ができたら終わりか。
4. 分かるなら対象リポジトリ側の関連パス・注意点。

依頼を出したら（経路と書式: [`docs/outbox-proposal.md`](outbox-proposal.md)）、**ユーザーに次を伝える**:

- 「ops-sync 側の PR → 対象リポジトリの同期 PR の順にマージされると届きます」
- **対象リポジトリのセッションに貼るコピペ用の指示文**（1つずつ・冒頭に1行の概要。Claude Code は
  最初の入力からセッションタイトルを生成するため）:

  ```
  <作業の1行概要>
  .ops-sync/tasks/<ファイル名> に依頼があります。読んで作業してください。
  ```

## 受ける側（`.ops-sync/tasks/` にファイルがあるとき）

- 現在のユーザー依頼がそのタスクを指しているなら、そのまま実行する。
- 別件の作業中に気づいたら、現在の依頼と両立する場合のみ対応し、そうでなければ存在をユーザーに
  伝えるに留める（勝手にセッションの目的を乗り換えない）。
- **完了したら、ops-sync 側の正本 `tasks/<owner>/<repo>/<ファイル名>` を消す**（MUST）。消さないと
  次の sync で `.ops-sync/tasks/` に復活し、別のセッションが同じ依頼を再実行する（`.ops-sync/tasks/` の
  ファイルは同期管理下なので、手元で消しても戻ってくる。MUST NOT: 手元のファイルを消して完了とする）。
  - 満たし方は起票と同じ2経路（選び方は → `docs/outbox-proposal.md`）: 正本への**直接 PR** なら
    `tasks/<owner>/<repo>/<ファイル名>` を削除する PR、**outbox** なら `種別: task-done` の提案。
  - 完了条件: その削除が ops-sync の main に入り、次の sync で `.ops-sync/tasks/` から消えている。
  - 作業の「なぜ」は通常どおりこのリポジトリの履歴ファイルに残す。

## ops-sync 側でできること

ops-sync のセッション（またはオーナー）は、`tasks/<owner>/<repo>/` にファイルを直接コミット／削除して
起票・消化できる（consumer のセッションが直接コミットすることはなく、正本への PR か outbox 提案を
経由する。→ `docs/outbox-proposal.md`）。ops-sync 自身への依頼はタスク機構を
使わず、ユーザーが ops-sync のセッションに直接指示する。
