## 2026-07-31 ジョブログ経由の漏れ（create-pull-request とブランチ名）を塞ぐ

- #127 で「ログの公開先は何についてのログかで決める」を入れ、`ci-logs` と自分の `tee` は塞いだ。その後
  **新実装の初回 run を実測したら、まだ漏れていた**。ops-sync（public）のジョブログに
  `D docs/history-inbox/<private のタスクスラッグ>.md` が出ていた。出所は
  `peter-evans/create-pull-request` で、この action は `git status` / `git commit` の出力を
  そのままジョブログへ流す。`uses:` ステップの出力は呼び出し側から抑制できない。
- **教訓は「自分の `run:` を直しただけで塞げたと判断しない」**。ジョブログへ落ちる経路は3つある:
  (1) 自分の `run:` の stdout/stderr、(2) `uses:` した action の出力、(3) **`with:` に渡した値そのもの**
  （`uses:` ステップの入力は必ずログに出る）。#127 は (1) しか塞いでいなかった。
- (2) の対処として `.github/actions/create-pr-quiet` を足した。`shared/` ではなく **ops-sync ローカル**に
  置いたのは、これが必要なのは「public な実行リポジトリから private リポジトリへ commit する」
  cross-repo バッチだけで、consumer に配る意味が無いため。ops-sync 自身に対する PR（取り込み・
  トゥームストーン整理）は公開されて当然なので `peter-evans/create-pull-request` のまま残した——
  実績のある action を必要の無いところまで置き換えない。
- (3) で cleanup ブランチ名を提案ファイル名の 12 桁ハッシュに変えた。`ops-sync/cleanup-<slug>` は
  ブランチ名だけで提案名が読めてしまう。ハッシュでも「同じバッチ＝同じブランチ＝open の PR を
  force-push で更新する」性質は保たれる。intake 側は public な ops-sync に立つブランチで、提案内容が
  そのまま公開 PR になるので slug のまま。
- 自前 PR 作成に移した分、`delete-branch: true` が無くなるので、各マージ側に `--delete-branch` を足して
  使い捨てブランチの後始末を保った。
- 既存のジョブログ（archive-task-history の 23 run）は API で削除した。`ci-logs` と違って git 履歴には
  残らず log retention（既定90日）で消えるが、待つ理由が無いため。retention の変更はリポジトリ設定で
  UI からのみ（REST に該当エンドポイントが無い）なのでオーナーに依頼した。
