## 2026-07-31 設計 doc から過去の run の記述を落とす（consumer 同期 PR にだけ出た指摘）

- `ops-sync-design.md` に「実際、詳細ログの分離を入れた直後の run で〜が公開ログに出ていた」
  「実際に起きた」と**過去の run の話**を書いていた。AGENTS_COMMON に
  「`docs/` の doc は障害記録・タスク履歴を除き**現在の姿だけ**を書く」があり、その違反。
  主張の説得力を上げるつもりで書いた一文だが、読み手は毎回「これは今の設計か、昔の話か」を
  切り分ける必要が出る。現在形の不変条件に書き直し、経緯はタスク履歴側（既に書いてある）に任せた。
- **この指摘は ops-sync の PR（#139/#140）には出ず、consumer 同期 PR（private #488）にだけ出た。**
  AGENTS.md「配布変更のダウンストリーム確認」が想定している経路の実例が、また1件増えた。
  今回は nikki-san / ops-runner の同期 PR には出ておらず private だけ——**同じ配布物でも
  どの consumer に出るかは一定しない**ので、1 repo 見て終わりにできない。
- 教訓としては「**根拠の書き方**」。設計 doc に事実の重みを足したいとき、過去形の事例を足すのではなく
  **不変条件を強く書く**（「最初の1つを塞いだだけでは残り2つから同じものが出る」）。事例は履歴に
  置いてあり、必要な人は git と履歴から辿れる。
