## 2026-08-03 クローズ済み PR 注記の根拠を実例で裏付ける

`codex-review-inbox` からクローズ済み（未マージ）PR を在庫から外したとき、完全ドロップにせず注記を残した
理由は「放棄された PR の指摘が `main` にも当てはまることがある」だったが、doc にはその一文しか無く、次に
読む人が「本当にあるのか？」を再調査する状態だった。実際に在庫に出ていた3件を確認したところ、
**注記の必要性を示す実例と、成り立たない反論の両方が出た**ので書き残す。

- nikki-san #547（放棄）の指摘と同じコードが #548 で `main` に入ったが、**#548 にはレビュースレッドが0本**。
  欠陥を指す文はクローズ済み PR にしか無く、それを読んだ人が起こした #551 で直るまで `main` に残っていた。
  → 「同じ変更が別 PR で入るならその PR にも同じ指摘が付くから拾える」は**反例つきで否定**される。
- 残り2件（#578 / #660）は PR 限りの指摘で、`main` には効かない（#578 は landed しなかったコードの話、
  #660 はその PR 自身の履歴フラグメントの話）。

3件中1件が「在庫の外に置くと誰も知らなくなるクラス」だった。注記は3日で消える数行なので、この頻度なら
保険として妥当という判断。逆に言えば注記が埋めるのは「同じ欠陥が別 PR で `main` に入り、その PR には
レビューが付かなかった」という穴だけで、それ以外の用途を期待しない。

なお、確認の過程で3件とも既に対応済み（未 resolve のまま残っていただけ）と分かったので、返信のうえ
resolve した。「載っている＝未対応」ではなかった典型例。
