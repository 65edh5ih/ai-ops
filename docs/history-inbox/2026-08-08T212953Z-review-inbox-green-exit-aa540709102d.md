## 2026-08-08 未対応在庫では run を落とさない（緑で終える）

`review-inbox` はマージ済み PR の未 resolve（🔴）が1件でもあると run を失敗させていた。一覧はファイルで
誰も見に行かないから badge に出す、という意図だったが、**在庫は消化されるまで毎時再検出される**ので
同じ1件で毎時 run failed メールが飛ぶ。オーナーから「メールがうるさい」と停止要求が出た＝
気づかせるための信号が、通知を読ませなくする原因になっていた。

そこで**赤の意味を「一覧が信用できない」に一本化**した。在庫の残高（🔴）は warning アノテーション＋
ジョブサマリの警告ブロックまでにし、run を赤にするのは `failures`（収集機構の故障。読めなかった対象を
「指摘ゼロ」と誤読させる fail-open）だけにする。在庫の有無で色が変わらなくなるので、赤＝要調査が保たれ、
毎時の繰り返しにもならない（故障は繰り返す性質のものではない）。

**未対応であること自体は異常ではなく在庫の残高**、というのが分け方の根拠。異常判定を残高に載せると、
残高がゼロになるまで警報が鳴り続ける設計になり、警報の意味が失われる。同種の「定期実行×消化されるまで
残る在庫」を CI から知らせたくなったら、失敗ではなく警告＋サマリに出すこと（設計の理由は
`shared/docs/ops-sync-design.md`「レビューの取りこぼし対策」に書いた。履歴だけに残さない）。

気づき口は run のメールではなく一覧ファイル（全体一覧＋各 repo のスライス）に寄せた。もともと
エージェント側の発火トリガは `.ops-sync/review-inbox.md` を読むことなので、こちらが本流。
