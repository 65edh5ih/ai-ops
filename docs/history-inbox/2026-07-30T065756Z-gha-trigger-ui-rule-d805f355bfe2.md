## 2026-07-30 UI の Actions 起動ボタン表示を共通ルール化

ある consumer の管理画面で「Actions を起動するボタンだけ配色＋バッジで区別する」を一度入れたが、
これは*その時にあったボタン*を直しただけで、**今後増えるボタンには何の強制力も無かった**（ユーザーの
依頼はここ）。ルールの置き場は共通/固有・常時/オンデマンドの2軸で決めた: 「印を付ける」という要求は
UI を持つリポジトリすべてに効くべきなので共通（`AGENTS_COMMON.md`）、ただし*どう*付けるかは UI 実装に
依存するので手順は `shared/docs/gha-trigger-ui.md`（オンデマンド）に逃がし、常時層には発火トリガと
2要件（視覚差＋ホバー不要のテキスト）だけ残した。**見た目そのものはリポジトリ間で揃えない**——揃える
べきは「印がある」という要件で、配色まで共通化すると各 UI のデザイン体系や CSS 変数と衝突する。

MUST NOT を「workflow を起動しないボタンには付けない」側にも置いたのは、元の作業で一番手間がかかったのが
対象外の判定だったから（Actions variables を書くだけ・ストレージ操作だけ・cron 任せ のボタンが混ざる）。
印を安全側に増やすと「特別な操作だ」という信号が薄まり、規約そのものが無効化される。同じ理由で手順1に
「ラベルや置き場所から推測せず、ハンドラのコードで dispatch 送信を確認する」を MUST で置いた。

レビューで2点直した。(1) **枠消費の文言は private リポジトリのときだけ**——この共通ブロックは public な
consumer にも配られ、public リポジトリの GitHub-hosted runner は無料なので、「起動＝枠を消費」を全体の
理由づけにすると誤りが混ざる。印の要求自体は可視性によらず必要なので、要求と理由づけを分けた。
(2) **`title` だけを文言要件の充足とみなさない**——タッチ・キーボード操作では押す前に読めない。実装者は
マウスで確認するので気づきにくく、スマホから使う管理画面では実質「押すまで分からない」になる。

配布経路の確認: `shared/**` は walk で自動的に拾われるので登録作業は不要（scratch に
`apply-shared.mjs` を実行し、doc 1つ＋ skill ミラー7つと manifest への追加を実測）。
README・ops-sync-design には手を入れていない: 構成表は `shared/**` を1行で扱い、個別の共通 doc は
（既存の他の SOP も含めて）行を持たないため。新しい仕組みは足していない。
