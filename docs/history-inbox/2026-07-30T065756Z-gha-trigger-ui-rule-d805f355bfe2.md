## 2026-07-30 UI の Actions 起動ボタン表示を共通ルール化

nikki-san の管理画面で「Actions を起動するボタンだけ amber ＋ `Actions` バッジ」を一度入れたが、
これは*その時にあった10個*を直しただけで、**今後増えるボタンには何の強制力も無かった**（ユーザーの
依頼はここ）。ルールの置き場は共通/固有・常時/オンデマンドの2軸で決めた: 「印を付ける」という要求は
UI を持つリポジトリすべてに効くべきなので共通（`AGENTS_COMMON.md`）、ただし*どう*付けるかは UI 実装に
依存するので手順は `shared/docs/gha-trigger-ui.md`（オンデマンド）に逃がし、常時層には発火トリガと
2要件（視覚差＋文言）だけ残した。**見た目そのものはリポジトリ間で揃えない**——揃えるべきは「印がある」
という要件で、配色まで共通化すると各 UI のデザイン体系と衝突する。

MUST NOT を「Actions を起動しないボタンには付けない」側にも置いたのは、nikki-san での作業で対象外判定
（`hmScan`・`btn-canon`・deploy-switch＝Actions variables を書くだけ）に一番手間がかかったから。印を
安全側に増やすと「特別な操作だ」という信号が薄まり、規約そのものが無効化される。同じ理由で手順1に
「ラベルや置き場所から推測せず、ハンドラのコードで dispatch 送信を確認する」を MUST で置いた。

配布経路の確認: `shared/**` は walk で自動的に拾われるので登録作業は不要（scratch に
`apply-shared.mjs` を実行し、doc 1つ＋ skill ミラー7つと manifest への追加を実測）。private の
`c-admin` worker は Actions variables を書くだけで dispatch しないため、既存の未表示ボタンは無い
（＝このルールによる遡及的な負債は発生しない）。
