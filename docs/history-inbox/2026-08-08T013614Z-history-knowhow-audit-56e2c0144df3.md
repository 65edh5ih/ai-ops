## 2026-08-08 履歴に溜まった再利用可能な知見を doc へ移す（過去分の洗い出し）

`task-history.md` 手順3（「今後は〜する」と読める文は履歴ではなく doc へ）を**過去の履歴に遡って適用**した
棚卸し。全リポジトリの `AI_TASK_HISTORY.md`・`history-archive/`・`history-inbox/`（4リポジトリ・約 430 エントリ）を
読み、教訓として書かれていた文をひとつずつ「該当 doc に既にあるか」で振り分けた。

**判断の基準**（次に同じ棚卸しをするとき用）: 「履歴にしか無い」だけでは移す理由にならない。移すのは
**次に同じ状況に入る人が、その doc を開く導線を持っている**ものだけ。導線が無い知見は doc を新設するより
先に「どのトリガで読まれるか」を決める必要があり、決まらないなら移しても読まれない（履歴と同じ）。

**大半は移す必要が無かった**。教訓が書かれたエントリの多くは、その作業自体が doc の改訂だった（＝既に
正本に入っている）か、一度きりの実装判断だった。移したのは**別々の作業で繰り返し踏まれている**もの——
同じ失敗が複数エントリ・複数リポジトリに現れていて、それでも doc に無かった7件に絞った。繰り返し回数を
選別の基準にしたのは、1回しか起きていない教訓は「次も起きる」の根拠が弱く、常時層・配布 doc の
コストに見合わないため。

**常時層（`AGENTS_COMMON.md`）に入れたもの**は、発火トリガが「doc を開こうと決める前」にあるものだけ:
主張を変えるときの全箇所洗い出し（doc 編集中に発火）・推測の断定禁止（完了報告の直前）・基点の鮮度
（push の直前）・incidents の宿題の引用（doc を読むとき）・2実装の突き合わせ。オンデマンド doc に置くと
「開かない人」には届かない種類のもので、逆に手順の詳細は入れていない。+931 文字（自動マージの目安 800 を
超えるが、これは7件を1回で入れたため。1件あたりは 100〜300 文字）。

**オンデマンド doc に入れたもの**は、既にトリガを持つ doc へ足した: SOP の対象を広げたときの導線追随
（`sop-format.md`）・外部 API エラーの残し方と slice の鮮度確認（`ci-logs.md`）・定期実行の頻度と時刻
（`actions-quota.md`）。最後の1件は doc の対象そのものを広げたので、**同じ PR で `AGENTS_COMMON.md` の
トリガ1行と skill の `description` も広げた**——ちょうど今回入れた「対象を広げたら導線も広げる」の
1件目の適用になる。

**この棚卸しで見えた構造**: 履歴に教訓が溜まるのは書き手の不注意ではなく、**教訓が生まれる瞬間と、それが
要る瞬間が別のタスクにある**ため。書いている本人にとっては「今の作業のなぜ」なので履歴が自然な置き場に
見える。だから「履歴に書くな」より「**どのトリガで読まれるか**を決めてから置く」のほうが実行しやすい。
