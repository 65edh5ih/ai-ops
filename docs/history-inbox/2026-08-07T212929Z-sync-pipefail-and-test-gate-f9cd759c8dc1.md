## 2026-08-07 配布の判定が CI で効いていなかった穴を塞ぐ

`apply-common.mjs` のマーカー検査は「壊れていたら黙って直さず失敗させる」設計だが、**その失敗が
CI で握り潰されていた**。`sync.yml` の3ステップが `... | tee /tmp/ci-logs/*.log` で、`run:` の
既定シェルが `bash -e {0}`——`shell: bash` を明記したときだけ `-eo pipefail` が付く——なので、
パイプの終了コードは tee の 0 になる。実測でも `bash -e -c 'false | tee /dev/null'` は rc=0。

結果、旧マーカーが残った consumer でも判定は素通りし、同期 PR が作られて direct マージまで進む。
**判定を厳しくする作業を重ねても、判定が読まれていなければ意味が無い**。`apply-shared.mjs` は
削除の伝播を含むので、途中失敗の部分適用がそのままマージされる分もっと悪い。3ステップとも
複数行 `run` にして `set -euo pipefail` を置いた。

**回帰テストを走らせる CI も無かった**（`grep -rn 'node --test' .github/` が 0 件）。テストを
足しても、次に判定を触る人がどちらかへ倒したときに気づける保証が無い。`prepare` ジョブに
`node --test` を置いた。`sync` は `needs: prepare` なので、落ちれば全 consumer への配布が止まる。

**これは PR のゲートではない**。このリポジトリに `pull_request` 起点の CI は無く、`sync.yml` は
main への push・cron・手動でしか走らない。止められるのはマージではなく**配布**（＋cron の
ドリフト自己修復）。`node --test` は `scripts/*.test.mjs` を全部走らせるので、配布に関係しない
スクリプトのテストが落ちても配布は止まる——「赤い main では配らない」が意図。

**現行マーカーの重複判定は緩めなかった**。旧マーカー側と同じ誤検知（本文に丸ごと引用すると
`ne=2` になり配布が止まる）は現行側にもあるが、区間の切り出し `findRegion` が `indexOf` で
位置を決める以上、引用と実マーカーを区別できない。緩めると引用の側を境界に選んで**本文を
削りうる**——誤検知して人に掃除させるより悪い側へ倒れる。代わりにエラー文へ「引用も数える」
と書き、人が引用を崩して再実行できるようにした。**両側を同じ形に揃えるのが常に正しいわけでは
ない**という判断の記録。
