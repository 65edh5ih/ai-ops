## 2026-08-03 Codex 積み残し（private/ops-runner 分）の消化

**自分が直した配布 doc の同期 PR に、その修正が生んだ新しい指摘が付いた**（ops-runner#56・private#512・#513）。
配布物を触ると同じ内容が3リポジトリの同期 PR でレビューされるので、**正本 PR には出ない指摘が下流でだけ出る**
——ops-sync 側で緑でも、下流の同期 PR を見るまで消化は終わっていない。

今回それが起きた3件:

- **design doc に PR 年代記を書いた**（#153）→ 現在形ルール違反。`docs/` は現在の姿だけを書き、経緯は
  git とタスク履歴に残す場所がある。根拠を doc に残したくなったら、**主張だけを doc に、実例は履歴に**置く。
  加えて、実例に挙げた PR がその時点の生成物（inbox）では 🟡 と表示されていて、doc が自分の生成元と
  矛盾しているという指摘も付いた（🟡 の誤表示自体は #152 で直した当のバグ）。
- **概念を2つに割ったのに、割り残しがあった**（#154 で「月枠の消費」と「直接課金」を分離）→ 概要文と
  手順2b が旧概念のままで、larger runner を有効化する操作に対応する文言が規約から消えていた。
  **区別を導入したら、その語が出てくる箇所を全部数える**（概要・トリガ・手順・完了条件・よくある失敗）。

その他、機序が非自明だったもの:

- **鍵の無いハッシュは秘匿にならない**（#487）。cleanup ブランチ名に提案ファイル名の 12 桁ハッシュを
  使っていたが、提案名は「日時＋人が読めるスラッグ」で推測できるので、候補をオフラインでハッシュして
  突き合わせれば復元できる（48ビットの一致確認は総当たりを妨げない）。**既に公開されている値**
  （consumer 名。`consumers.txt` にある）に置き換えた。1 run = 1 consumer 分のバッチなので、
  consumer ごとに固定でも掃除 PR の再利用性は落ちず、むしろバッチ先頭が変わるたびに2本目の掃除 PR が
  できる問題も消える。切替時に取り残される open な cleanup PR が無いことは事前に確認した。
- **`|| true` で列挙失敗を握りつぶしていた**（#478）。「削除対象なし」と「一覧が取れなかった」が同じ緑に
  なるので、取得 URL を含む public run が警告も無く残り続ける。掃除の付随処理なので run は落とさず
  warning にした（エラー本文は URL を含みうるので出さない）。
- **設定ファイルは本番の binding の証拠にならない**（#482）。設定が本番より進んでいる／遅れていると、
  期待どおり 0 件が返っても本番は別 DB を向いたまま互換コードを消すことになる。稼働中バージョンの
  binding と突き合わせてから使う、に変えた。
- **publish だけ先に出して読み手が無い状態を「現行構成」と書いていた**（#497）。`decision.json` の
  consumer 側リーダーは未実装で、`auto` にしても切り替わらない。未実装であることを doc に明記した。
