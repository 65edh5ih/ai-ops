## 2026-07-31 shared-file の本文をバイトそのままで書き込む

`shared-file` のベースハッシュをバイト厳密にした（#133・#134）のに、**書き込み側が正規化したまま**
だった。`stripFrontmatter()` が `.trim()` し、書き込みが `+ '\n'` していたため、提案本文と違うバイトが
書かれる。「ベースが一致したので安全」と判定した直後に境界バイトを黙って書き換えることになり、
バイト厳密にした意味が消えていた（Codex 指摘・#134 のマージ後に付いたもの）。

`stripFrontmatterRaw()`（trim しない）を分け、`shared-file` はそれを使って**そのまま書く**。
空判定は `!fileBody.trim()` に変えて、改行だけの本文が通らないようにしてある。
`common-block-edit`・`task`・`task-done` は従来どおり trim 版を使う（埋め込み・比較用途で、
バイトが意味を持たない）。

**検査と書き込みは対で直す**。片方だけ厳密にしても、緩い側が最後に上書きすれば保証は成立しない。
今回は「検査を厳密化する」変更だけを見て、その値が守るはずの書き込み経路を見ていなかった。

**この指摘は、マージ後に付いて誰も見ていなかった。** `codex-review-inbox` の一覧を実測確認した
ついでに見つかったもので、まさにその一覧が存在する理由どおりの拾われ方をした（#134 のエスカレーション
を入れた本人が、その仕組みに拾われた形）。
