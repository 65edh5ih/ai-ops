## 2026-08-03 public repo に private の識別子を書かない範囲を広げる

配布 doc → タスク履歴 → **コミットメッセージ**と、同じ識別子が3回連続で public 側に残った。1回目は
doc、2回目は「doc から履歴へ移せば隠れる」という誤解、3回目は PR 本文がそのままコミットメッセージに
なる経路。**塞いだつもりの穴が別の出口から出ていた**ので、規約の対象を「doc」ではなく
「public な履歴として残るものすべて（doc・履歴フラグメント・コミットメッセージ・PR タイトル/本文）」
に広げて AGENTS.md に書いた。

判断軸は「どの層に書くか」ではなく**そのリポジトリが public か**。ops-sync では consumer 名
（`consumers.txt` で公開済み）を超える情報を書かない。

もう1件、**doc に「実装が無い」と断定して事実と食い違った**件も直した。ある consumer には
`decision.json` を読んで経路を自動で切り替える実装が既にあり、「読み手はまだ無い」という記述は
**その consumer の運用者に「`auto` にしても何も起きない」と誤解させる**（実際は本番の経路が人手なしで
変わる）。**consumer ごとに違いうるものを配布 doc で断定しない**——「実装しているかは consumer ごとに
違う。`auto` を選ぶ前に自分のリポジトリの実装を確認する」と書くのが正しい形だった。元の記述は
別の consumer で「未実装なのに現行構成のように読める」という逆向きの指摘に応えて足したもので、
**片方の consumer だけを見て一般化した**のが原因。
