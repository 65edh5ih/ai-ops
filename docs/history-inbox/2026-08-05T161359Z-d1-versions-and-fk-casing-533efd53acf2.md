## 2026-08-05 段階的デプロイと識別子の大文字小文字を SOP に反映

D1 の SOP に3件。いずれも**マージ後の consumer 同期 PR に付いたレビュー**で出た（本体 PR には出なかった）。

**(1) 「有効なバージョンは1つ」と決めつけていた**。段階的デプロイ（`versions deploy` の
`<version-id>@<percentage>`）では複数バージョンが同時に本番を受け持つ。片方だけ見て「これが本番の DB」と
決めると、まだトラフィックを受けている側を見落とす。**トラフィックが 0 でない全バージョン**を確認する形にした。
撤去手順側にも同じ罠があり（分割が残っている間は**旧版の ensure が列を作り直す**）、そちらにも書いた。
この2つは同じ「1バージョンしか見ない」前提から出ている。

**(2) FK 検出の比較が大文字小文字を区別していた**。SQLite の識別子は大小を区別しないのに
`pragma_foreign_key_list` は**宣言どおりの表記**を返す（実測: 子が `REFERENCES Parent(...)` なら `Parent`）。
素の `=` だと 0 件になり、**検査が「異常なし」で通る**。見落としが最悪の形で出る箇所なので `COLLATE NOCASE` を
MUST にした。列名側も同じ性質なので併記。**「探すときは広く」の原則がここにも効く**——同じ判断を、
前回は部分一致の扱いで、今回は大文字小文字で間違えた。

**(3) public リポジトリに private consumer の運用詳細を書いていた**。前回の履歴フラグメントに、別リポジトリの
セッションで得た具体的な構成情報（数量・同名の有無・どのコンポーネントが書くか）を根拠として書いてしまった。
このリポジトリは public で、履歴フラグメントも開示規約の対象。**教訓は「間接証拠に頼らざるを得なかった」まで
一般化すれば十分残る**ので、具体を落とした。一般化の判断を「doc 本文かどうか」でしていたのが誤りで、
判断軸は**このリポジトリが public か**（AGENTS.md にそう書いてある。読んだのに適用を外した）。
